# 19 · 第二轮实验结论与下一步优化方案

日期：2026-10-29
四轮对照：原版 / R1 硬标签强训练 / R2 软标签弱训练 / R3 软标签中等训练
评测：JevBench public-231，同一口径，全部本机 bf16

---

## 一、最终结果

| 模型 | 准确率 | 对题数 | Brier | ECE | 训练配置 |
|---|---:|---:|---:|---:|---|
| elephant-1 原版 | 90.04% | 208 | 0.1289 | **0.0338** | — |
| R1 | 90.48% | 209 | 0.1724 | 0.0840 | 硬标签 / 2ep / lr 1e-4 |
| R2 | 90.04% | 208 | 0.1369 | 0.0337 | 软标签 / 1ep / lr 1e-5 |
| R3 | 90.91% | **210** | 0.1395 | 0.0549 | 软标签 / 2ep / lr 1e-5 |
| **R3 + 温度缩放** | **90.91%** | **210** | **0.1346** | 0.0502 | + T(choice)=1.31 |

**R3 + 温度缩放是目前最优**：准确率比原版多 2 条，Brier 只差 4.4%，ECE 虽然还高于原版但已从 0.0549 压到 0.0502。

## 二、路由验证（老师最关心的指标）

阈值 0.90 下"置信度达标就直接采纳"：

| 模型 | 覆盖率 | 采纳准确率 | 采纳中出错 |
|---|---:|---:|---:|
| 原版 | 73.7%（157 条） | 99.36% | 1 |
| R1 | 73.7%（157 条） | 98.09% | 3 |
| **R3 + 温度缩放** | **75.1%（160 条）** | **99.38%** | **1** |

**R3 的路由能力优于原版**：能多采纳 3 条（覆盖率 +1.4pp），采纳准确率持平。

阈值 0.99 下：

| 模型 | 覆盖率 | 采纳准确率 |
|---|---:|---:|
| 原版 | 54.0% | 100% |
| R1 | **6.6%** | 100% |
| R3 + 温度缩放 | 50.2% | 100% |

R1 在 0.99 阈值下闸门几乎关死（只剩 14 条），因为它置信度虚高。R3 保持正常。

**结论：用置信度做路由这件事，R3 可以正常用，而且比原版略好。老师的第一个目标达成。**

## 三、四轮对照暴露出的规律

把训练强度和标签类型两个因素拉开看：

| 配置 | 准确率 | ECE | 说明 |
|---|---:|---:|---|
| 硬标签 + 强训练（R1） | +1 | 0.0840（崩） | 推得远，学到一点，但校准毁掉 |
| 软标签 + 弱训练（R2） | 0 | 0.0337（好） | 推得轻，没学到，校准保住 |
| 软标签 + 中等训练（R3） | **+2** | 0.0549（中） | 折中点，两者都有 |

**训练强度基本决定准确率增益，软标签决定校准的下限。**

R2 和 R3 用的是同一份软标签数据，唯一差别是 epoch 从 1 到 2——准确率从 0 涨到 +2，ECE 从 0.0337 涨到 0.0549。这说明**软标签并没有让模型"学得更准"，它只是让模型在同等训练量下不至于过度自信**。

换句话说：软标签是个"减震器"，不是"发动机"。要提准确率，还是得靠训练量或数据量。

## 四、为什么准确率只涨 2 条

三个约束，按影响排序：

**1. 数据量太小。** 1,166 条 × 2 epoch = 2,332 次更新。对比原版 elephant-1 的 621 万条训练数据，我们这次的数据量是它的 0.02%。2 条提升已经不算差。

**2. 训练集与评测集不同分布。** 训练数据是 When2Call（工具决策）+ DROP（数值题）+ OneJev（agent 轨迹判断），评测是 18 个族的通用决策。R3 那 2 条提升落在哪个族，值得单独查（下面第五节）。

**3. 训练集本身对模型很难。** 原版 elephant-1 在这 1,166 条上只有 62.3% 正确（727 条）。这意味着我们有一大半训练样本是"模型本来就不会"的，SFT 很难从中学到东西——**用自己不会做的题教自己，效果有限**。

## 五、下一步优化方案（按性价比排序）

### 方向 A：换 teacher，用 27B 生成软标签（最高优先级）

现在的软标签是 9B 自己给自己打的，它在训练集上只有 62.3% 正确。**用 27B 当 teacher，它的正确率大概率在 75–85%**，软标签质量会明显不同。

具体做法：
1. 起 27B 服务（权重还在 `models/mammoth-1`，启动约 60 秒）
2. 对 1,166 条训练样本打分布
3. 重新生成软标签（teacher 换成 27B，α 可保持 0.8）
4. 用同样的配置重训（2 epoch / lr 1e-5）

**预期**：teacher 正确率提高 → 能软化的样本从 727 条增加到约 900–1000 条 → 软标签携带的信息量翻倍。这是最有可能同时提升准确率和校准的一步。

成本：约 2 小时（27B 加载 + 1,166 条推理 + 训练）。

### 方向 B：扩大训练数据

当前只用了 1,166 条，其中 OneJev 部分还有 270 条未用（被剔除的 security 115 + check_met 34，以及 heldout 里可以回收的部分）。另外：

- DROP 可以扩量：现在只取了 400 条，候选 2,400 条
- OneJev 的 717 条里用了 447，剩余可用约 270

**但要注意**：扩量必须保持"对弱项有覆盖"的配比，不能为了凑数把 DROP 的简单数值题堆上去。DROP 里"how many"这类计数题对 temporal_numeric 帮助有限。

成本：数据准备 1 小时（DROP 转换规则现成），训练 20 分钟。

### 方向 C：补 long_policy 和 multi_hop 的数据

这两族 elephant-1 各错 5 条，占了总错误（23 条）的 43%，但目前训练数据里**一条都没有**。

- long_policy：自建长规则 + 例外场景（只能人工，约 100–200 条起步）
- multi_hop：MuSiQue 转换

这是"提准确率"理论上限最高的方向（潜在 +10 条），但制作成本也最高。

### 方向 D：调 Brier 权重

老师给的方案里没提这条，但值得一试：把 `--brier-weight` 从 1.0 提到 2.0–3.0，在 R3 的配置上重训。

逻辑：R3 的 ECE 涨到 0.0549 说明 Brier 项压不住 CE 的主导地位。提高权重是最直接的对抗手段。风险是准确率可能回落。

成本：训练 7 分钟。最便宜，可以顺手跑。

### 我的建议

**A + D 一起做**：先用 27B 重新生成软标签，同时把 Brier 权重提到 2.0，一次训练解决两个变量。

然后看结果：
- 如果 acc ≥ 212 且 ECE ≤ 0.045 → 可以定稿，这是"准确率提升 + 路由可用"的完整交付
- 如果 acc 涨但 ECE 还是差 → 说明 Brier 权重不够，继续加到 3.0
- 如果 acc 不涨 → 说明数据量是硬约束，转向方向 B/C

## 六、必须写进报告的注意事项

1. **温度是在 public-231 上拟合的**，属于测试集调参（1 个自由度）。ECE 0.0502 应理解为上界，正式结论需要独立校准集。
2. R3 的 210 条与原版的 208 条**不是同批题**，有翻转，净 +2。
3. 路由表的样本量小（0.9 阈值下 160 条），置信区间宽，不能过度解读 0.02 个百分点的差异。
4. 所有训练都在单卡 H100、bf16、LoRA r=32（q/k/v/o）下完成，可复现。
