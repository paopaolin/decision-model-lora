# 跨 benchmark 泛化评测：LoRA 有没有伤到通用能力

> 执行时间：2026-10-29
> 数据：4 个公开数据集、1,200 条，与训练配比零交集
> 模型：elephant-1 9B 基线 / +R3 LoRA / +R3 温度缩放 / mammoth-1 27B

## 一、为什么必须做这一步

前面所有结论都建立在 JevBench public-231 上，而那 231 条已经被用过两次：拟合温度（T=1.31）、挑选 checkpoint。继续在它上面挤分数，等于拿测试集做模型选择，结论会越来越虚。

jevbench 的 README 有一条明确要求：*Training on the public split must be disclosed.* 我们没有在它上面训练（去污染六项重合为 0），但**用它调了温度**，这一点必须披露，也必须有另一个集合来交叉验证。

所以这一步要回答一个问题：**R3 在 231 条上多对的 2 条，是不是拿通用能力换来的？**

## 二、数据构造

四个数据集都不在训练配比里（训练用的是 When2Call / DROP / OneJev-Data），所以基线 vs R3 的差异是纯粹的迁移效果。

| 数据集 | 规模 | 测什么 | 选项构造 | 协议 |
|---|---:|---|---|---|
| banking77 | 300 | 细粒度意图路由（77 类） | 8 选 1，1 正 + 7 随机负 | CC-BY-4.0 |
| clinc150 | 300 | 更难的路由（150 类） | 8 选 1，1 正 + 7 随机负 | CC-BY-3.0 |
| ai2_arc | 300 | 科学与常识推理 | 原生 3–5 选项，不改造 | CC-BY-SA-4.0 |
| imdb | 300 | 长文本判断 | 2 选 1 | Apache-2.0 |

三处刻意的设计：

**选项顺序打乱。** gold 位置分布 121/118/117/122（四个位置），测试笔记在 `meta.json`。

**负样本从别的类别里随机取。** 这一步后来被证明是这套数据的主要弱点，见第五节。

**IMDB 过滤到 600–2400 字符。** 太短的评论体现不出长文本判断，太长的可能超窗口。过滤后 state 中位数 1,016 字符，是 JevBench 那 70 字符的 14 倍。

类别分布上做了平衡采样（按类别轮转），避免高频类淹没结果。clinc150 的 `out_of_scope` 全部剔除——在 8 选 1 闭集里它无法被正确回答，会把噪声当成能力差异。

## 四、四个发现

### 1. 没有灾难性遗忘，但分辨率只到 ±0.8 个点

配对比较：基线对/R3 错 2 条（`xb-arc-135`、`xb-clinc150-000`），基线错/R3 对 1 条（`xb-arc-058`），净 −1 条。McNemar 精确检验 **p = 1.000**（不一致对只有 3 个）。

结论是"没有可检测的退化"，但不能说成"完全无损"。基线准确率 97.92%，二项标准误 0.41 个点，**95% 区间约 ±0.81 个点**。所以只能排除大于 0.8 个点的损伤，更细的差异这套题看不见。

### 2. R3 的过度自信是跨域复现的，不是 JevBench 特有

这是本次最有价值的一条。看高置信错误数：基线 8 条，R3 **14 条**，翻近一倍。同时平均置信度从 0.9760 升到 0.9867，覆盖从 93.4% 升到 96.0%。

也就是说，R3 在四个从没见过的数据集上同样变得"更敢说、更容易说错"。这和 231 条上观察到的现象（置信度 ≥0.9 的题从 168 涨到 217、高置信错误从 1 涨到 14）**方向完全一致**。

一个只在单一数据集上出现的现象可能是噪声，在两个互不相干的评测体系上同时出现，就该当成真实属性了。

还有一处细节值得注意：R3 的 gold 概率（0.9714）比基线（0.9631）**更高**，但 NLL（0.0779）比基线（0.0737）**更差**。概率上去了、似然下来了，唯一解释就是**答错时错得更自信**。这是校准变坏的典型指纹。

### 3. 在 JevBench 上拟合的温度，跨域仍然管用

| | NLL | 高置信错误 | 覆盖 |
|---|---:|---:|---:|
| R3（未校准） | 0.0779 | 14 | 96.0% |
| R3 + T=1.31 | **0.0735** | **9** | 94.5% |
| 基线 | 0.0737 | 8 | 93.4% |

温度是在 231 条上拟合的，拿到 banking77 / clinc150 / ARC / IMDB 上，**NLL 从 0.0779 修到 0.0735，比基线还好一点**；高置信错误从 14 降到 9，基本回到基线的 8。

这说明过度自信是个**全局的尺度问题**，不是某个领域的偏移——所以一个标量温度就能跨域迁移。这对部署是实际好消息：不需要为每个新场景重新拟合温度。

（这一步是离线算的：`p' ∝ p^(1/T)`。第一版我把指数写成了 `T` 而不是 `1/T`，方向反了，结果是覆盖率上升、NLL 变差，正好是锐化的特征。NLL 变差这个反常信号把 bug 暴露出来了。）

### 4. 27B 在这里几乎没有优势，说明这套题饱和了

27B 在 JevBench 上比 9B 高 **3.9 个点**，在这 1,200 条上只高 **0.42 个点**。这是天花板的典型标志——不是 27B 变弱了，是题太简单，三代模型都顶到 98% 附近。

唯一还有区分度的是 NLL：27B 0.0597 vs 9B 0.0737，差 0.014，比准确率上的差距明显得多。**准确率饱和之后，概率质量仍是有效的区分指标。**

分数据集看，27B 的优势几乎全部来自 ARC（+2.0 个点），意图类的两个数据集只高 0.33 和 0 个点。而 IMDB 上 27B **反而比 9B 低 0.67 个点**——长文本二分类这类任务，加大参数没有收益。

## 五、这套数据的弱点，必须写清楚

**随机负样本让意图任务变得太容易。** banking77 是 77 类里随机抽 7 个做干扰项，大多数干扰项一看就不对（问"怎么激活卡片"，干扰项是"支票存款后余额未更新"）。所以 98.67% 考的其实是粗粒度路由，不是细粒度区分。

**绝对值不可比文献。** 8 选 1 是我们的构造，不是 banking77 / clinc150 的原生协议（原生是 77 类、150 类全标签空间）。所以 98.67% 不能和文献里 BERT 的 93% 之类放在一起，只能做模型间横向比较。

**污染不可知。** 这四个数据集都是公开的，很可能在 elephant-1 那 621 万条训练数据里（那个数据集的构成不公开）。所以绝对水平可能被高估。但基线、R3、27B 共享同一份潜在污染，**模型间的差值是干净的**。

**样本量。** 每个数据集 300 条，单数据集的标准误约 1 个点，分数据集看差异时不能过度解读。

## 六、这套评测回答了什么、没回答什么

**回答了：**

- R3 没有可检测的通用能力退化（净 −1/1200，p=1.00），可以排除大于 0.8 个点的损伤
- R3 的过度自信是真实属性，跨 4 个数据集复现
- JevBench 上拟合的温度能跨域迁移，部署时不需要为每个场景重拟合
- 27B 的收益在通用任务上远小于 JevBench，说明 JevBench 那 3.9 个点主要来自决策特有的推理族

**没回答：**

- 细粒度意图区分能力有没有退化（随机负样本测不出来）
- 低于 0.8 个点的损伤（分辨率不够）
- 长文档多跳、规则例外这类任务（IMDB 只测了情感二分类，不是真正的高难度长文本推理）

## 七、如果要提高分辨率

把负样本换成**难负**：对每条查询，从 77 个意图里挑与查询词重叠最多的 7 个，而不是随机抽。这样测的才是"相近意图能不能分开"，预期准确率会掉到 80–90% 区间，区分度足够。

代价很小：数据重建不花钱，三个模型各跑一遍约 3 分钟推理，加上服务各 85 秒加载。可以一个模型一个模型串行跑，全程只占一张卡。

这是目前最值得补的一块，因为它直接对应 R3 训练数据里量最大的 When2Call（工具/意图路由），是唯一可能真出问题的地方。

## 八、复现

```bash
# 构建 1200 条（CPU，会下载约 45MB）
python build_crossbench.py

# 每个模型跑一遍（需对应服务在 8100 端口）
python -m jevbench.cli run --tasks data/crossbench/all.jsonl \
  --adapter typesafe --endpoint http://127.0.0.1:8100 --model <name> \
  --key-env= --results results/crossbench/<name>/results.jsonl \
  --raw-dir results/crossbench/<name>/raw \
  --ledger results/crossbench/<name>/ledger.jsonl \
  --manifest results/crossbench/<name>/manifest.json

# 汇总 + 分析
python -m jevbench.cli summarize --tasks data/crossbench/all.jsonl \
  --results results/crossbench/<name>/results.jsonl \
  --ledger results/crossbench/<name>/ledger.jsonl \
  --public-export results/crossbench/<name>/summary.json
python analyze_crossbench.py
```
